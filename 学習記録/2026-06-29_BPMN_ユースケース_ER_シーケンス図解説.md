## 図の全体像：何のために使い分けるか

| 図の種類 | 視点 | 答える問い |
|----------|------|------------|
| BPMN | 業務の流れ | **誰が・何を・どの順番でするか** |
| ユースケース図 | 機能の整理 | **誰が・何の機能を使うか** |
| ER図 | データの構造 | **どんなデータが・どう関係するか** |
| シーケンス図 | 処理の流れ | **誰と誰が・何をやり取りするか** |

これらは全部「同じシステム」を**違う角度から**見た図。

## 1. BPMN（ビジネスプロセスモデル）

### 記号の読み方

```
緑の●     → 開始
赤の⊗     → 終了
角丸四角  → タスク（誰かがする作業）
◇（菱形） → 分岐（条件によって処理が変わる）
水平の線  → スイムレーン（誰の作業かを区別する帯）
```

### この図が表していること（library_bpmn.png）

```
利用者スイムレーン:
  開始 → 蔵書を検索 → 見つかった？
                          ↓はい
                       貸出申請

職員スイムレーン:
  貸出申請書を受け取る → 貸出登録 → 貸出票発行 → 終了
```

### コードとの対応

```
利用者の操作 → search.html（蔵書検索画面）
職員の操作   → loan.html（貸出登録画面）
```

スイムレーンの境界線 = 画面の役割分担

## 2. ユースケース図

### 記号の読み方

```
棒人間（アクター） → システムを使う人
楕円              → ユースケース（システムが提供する機能）
システム境界（枠） → この枠の中がシステムが担う範囲
«include»         → 必ずセットで実行される
«extend»          → 条件次第で追加される
```

### BPMNとの違い

- BPMN：「手順・順番」を表す
- ユースケース図：「誰が何の機能を持つか」だけを表す（順番は関係なし）

要求定義書の機能要求（FR-01〜FR-17）をそのまま図にしたもの。

### «include» の具体例

```
「貸出状況を確認する」─«include»─▶「検索する」

→ search.html で available_copies を表示するために
  必ずDBを検索している部分がこれに対応。
```

## 3. ER図（Entity-Relationship図）

### 記号の読み方

```
四角（エンティティ） → テーブル
PK                  → 主キー（一意な識別子）
FK                  → 外部キー（別テーブルを参照）

線の端の記号（多重度）:
  ||  → 必ず1つ
  |○  → 0または1つ
  |<  → 1つ以上
  ○<  → 0以上（多数）
```

### この図が表していること（library_erd.png）

```
BOOKS 1 ──────────< LOANS    （1冊の本 = 複数の貸出記録）
MEMBERS 1 ──────────< LOANS  （1人の利用者 = 複数の貸出）
BOOKS 1 ──────────< RESERVATIONS
MEMBERS 1 ──────────< RESERVATIONS
```

### コードとの対応

ER図の関係 → `database.py` の外部キー定義

```python
FOREIGN KEY (book_id)   REFERENCES BOOKS(book_id)
FOREIGN KEY (member_id) REFERENCES MEMBERS(member_id)
```

ER図の関係 → `models.py` の JOIN

```python
SELECT m.name, b.title, l.due_date
FROM LOANS l
JOIN MEMBERS m ON l.member_id = m.member_id
JOIN BOOKS   b ON l.book_id   = b.book_id
WHERE l.returned_at IS NULL
```

## 4. シーケンス図

### 記号の読み方

```
上部の四角        → 登場人物・コンポーネント
→ 実線矢印        → メッセージの送信（関数呼び出し）
←- 点線矢印       → 応答（戻り値）
[ ] の点線四角    → 条件分岐
時間の流れ        → 上から下へ
```

### 貸出シーケンス（seq_loan.png）とコードの対応

```
職員 → 貸出画面：利用者ID・蔵書IDを入力
貸出画面 → 貸出管理処理：registerLoan(memberId, bookId)
貸出管理処理 → DB：SELECT available_copies   ← models.py の在庫確認
[在庫あり] の場合のみ続行
貸出管理処理 → DB：INSERT INTO LOANS          ← models.py のINSERT
貸出管理処理 → DB：UPDATE available_copies - 1 ← models.py のUPDATE
```

```python
# models.py の loan_book() がこのシーケンスの実装
def loan_book(book_id, member_id):
    cursor.execute("SELECT available_copies FROM BOOKS ...")  # SELECT
    if book["available_copies"] <= 0:
        return False, "在庫なし"                              # [条件分岐]
    cursor.execute("INSERT INTO LOANS ...")                   # INSERT
    cursor.execute("UPDATE BOOKS SET available_copies - 1 ") # UPDATE
```

シーケンス図の1行 = コードの1処理

## 4つの図の設計における役割

```
要求定義書（文章）
    ↓ 業務の流れを図にする
  BPMN「誰が何をどの順番で？」
    ↓ 機能を整理する
  ユースケース図「誰がどの機能を使う？」
    ↓ 扱うデータを整理する
  ER図「データはどう関係する？」
    ↓ 処理の詳細を設計する
  シーケンス図「誰と誰が何をやり取りする？」
    ↓
  コード実装
```

文章だけの要求定義書を段階的に図に変換することで、
実装前に設計の抜け漏れを発見できる。
